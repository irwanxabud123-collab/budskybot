# Budsky V9 Repair Status — 2026-09-07

## Repairs completed in this pass

1. **Backtest train/test leakage fixed.** Training trade outcomes are now truncated at the chronological train/test boundary. A training candidate is used for calibration only when its outcome resolves before the test boundary.
2. **Backtest trade direction corrected.** Backtest trades generated by the bullish long-entry path are now recorded as `BUY` instead of the previous hardcoded `SELL` label.
3. **Deterministic CSV fixture added.** `datasets/budsky-backtest-fixture.csv` is explicitly synthetic and exists only for pipeline validation.
4. **Real OHLCV source instructions added.** `datasets/README.md` documents the official GeckoTerminal pool OHLCV endpoint and the exact CSV contract expected by `loadCsv()`.
5. **Native OHLCV fetch helper added.** `scripts/fetch-geckoterminal-ohlcv.mjs` downloads GeckoTerminal pool OHLCV and converts it into the bot's CSV schema without adding a new npm dependency.

## Remaining blocker — package-lock.json

The repository still does not contain `package-lock.json` because this execution environment cannot reach the npm registry. DNS/network access to `registry.npmjs.org` is unavailable and `npm install` fails with `EAI_AGAIN`. `npm install --package-lock-only --offline` also fails because the required package metadata is not cached.

A hand-written or copied lockfile would be unsafe because it would not be proof that this exact dependency graph was resolved and installed. Therefore no fake lockfile was added.
